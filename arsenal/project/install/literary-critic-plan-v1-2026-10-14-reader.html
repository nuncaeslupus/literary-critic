▸Technical solution

▸Architecture overview

Three independent pieces, then the prompts that use them, then the owner's hand tests that decide the one-click path:

  1. Version stamp (kit.py): the kit and Skill zips carry a VERSION file; lc doctor reports version, built, source.
  2. Update check (kit.py, lc doctor --json): newest release tag over HTTPS (stdlib urllib, 3 s timeout, once a day), compared with version; yes / no / unknown, silent on any failure.
  3. Live-first locate (word_live.py): ask doc-control capabilities for the live engine; live.select first, then the computer-use steps (today's behaviour), then the plain locator. Only dc.py talks to doc-control.
  4. Prompts: 05-setup.md turns update_available into one plain sentence at conversation start and resumes from an existing working folder; 80-live-word.md handles how: live.
  5. One-click live install: owned by doc-control (D-3). Here only the wizard offers it, on the surfaces the Q-1 result allows.

▸Technology choices

Choice Justification
stdlib urllib for the tag read runtime is stdlib only (AGENTS.md rule 9)
release tags as "latest" (Q-4) no extra file to keep in sync; tags already mark releases
live through dc.py only dc.py imports doc-control (architecture rule)

▸Out of scope

  • Packaging doc-control's live engine or MCP server (doc-control's session, Q-2).
  • Any change to the working-folder format.
  • Fixing the desktop app's always-on-top window after computer use.
